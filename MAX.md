# Бот заявок MAX

Интеграция подготовлена 12 октября 2026. Бот: `se14652009_bot`.
Официальное API: https://dev.max.ru/docs-api

Бот принимает уведомления о заявках и позволяет отмечать их обработанными,
переносить в список для перезвона, смотреть статистику и получать CSV.
Админка сайта и бот используют одну базу заявок. Изменения товаров остаются
в веб-админке. Telegram-код больше не запускается.

## Что нужно от владельца

1. Опубликованный бот MAX и его токен (уже созданы).
2. Добавить настройки в закрытый `.env` на VPS.
3. После обновления сайта подключить **свой** личный диалог через `/admin/max`.

Пароль сайта в MAX вводить не надо. У MAX нет возможности удалить сообщение
пользователя в личном диалоге, поэтому подключение использует одноразовую
ссылку из админки. Каждая ссылка действует 10 минут и используется один раз. Новая ссылка не
отменяет предыдущие приглашения. Можно подключить несколько пользователей
в личных диалогах; групповые чаты игнорируются. Для каждого сотрудника
создавайте отдельную ссылку. Все подключённые пользователи получают заявки,
могут менять их общий статус и выгружать CSV. Доступ конкретного пользователя
отменяется отдельной кнопкой в админке или в его диалоге с ботом.

## Обновление существующего VPS

Выполните из `~/GreenGarden`. Если на сервере менялся Compose для Telegram,
сначала сохраните его правки (без `.env`) и верните отслеживаемый файл:

```bash
git diff -- docker-compose.yml > ~/greengarden-compose-before-max.patch
git restore -- docker-compose.yml
git pull --ff-only origin main
```

Проверьте `docker-compose.override.yml` / `.yaml`, если такой файл создавался.
Уберите из него только старые `api.telegram.org` в `extra_hosts` и Telegram
настройки IPv6. Другие нужные настройки перенесите после просмотра сохранённого
patch. Для MAX закреплять IP или выключать IPv6 не требуется.

Откройте `nano .env`. Существующие DOMAIN, SITE_ADMIN_PASSWORD и остальные
настройки сайта сохраните. Добавьте:

```dotenv
MAX_BOT_TOKEN=вставьте_настоящий_токен
MAX_BOT_USERNAME=se14652009_bot
MAX_WEBHOOK_SECRET=вставьте_случайную_строку
MAX_CA_FILE=/app/backend/certs/max-ca.pem
MAX_TIMEOUT=10
```

Для `MAX_WEBHOOK_SECRET` сгенерируйте отдельную строку командой
`openssl rand -hex 32` и вставьте результат в `.env`.
Токен/секрет не отправляйте в GitHub и не вставляйте в сообщения поддержки.
В `.env` токен должен быть записан буквально; символ `$`, если появится при
перевыпуске, требует экранирования по правилам Docker Compose.
Старые TELEGRAM_BOT_TOKEN и TELEGRAM_ADMIN_PASSWORD больше не используются.

```bash
chmod 600 .env
sudo bash deploy/update.sh --no-pull
docker compose exec -T app python backend/max_setup.py check
docker compose exec -T app python backend/max_setup.py subscribe
docker compose exec -T app python backend/max_setup.py status
```

Пересобираются **оба** образа: app содержит новый клиент MAX, nginx — маршрут
webhook. `MAX_WEBHOOK_URL` Compose формирует из DOMAIN, например
`https://green-courtyard.space/api/max/webhook`. Метод subscribe регистрирует
эту ссылку в MAX с секретом; status показывает подписки без их секретов.
При смене домена повторите subscribe для нового адреса и удалите старую
подписку в MAX, чтобы не получать события на два сервера.

## Подключение и проверка руками

1. Войдите в `https://green-courtyard.space/admin` с паролем сайта.
2. Откройте раздел **MAX**, нажмите **Создать ссылку подключения**.
3. Откройте ссылку в собственном MAX или передайте нужному сотруднику; нажмите **Начать**. Для следующего человека создайте новую ссылку.
4. Обновите `/admin/max`: должен появиться подключённый диалог.
5. Отправьте тестовую заявку с сайта и заказ с двумя товарами из корзины.
6. Проверьте имя, телефон, количество товаров и комментарий в уведомлении.
7. Нажмите **Обработано** / **Перезвонить**: статус должен измениться и в
   карточке MAX, и в `/admin/leads`.
8. Проверьте статистику, список для перезвона и экспорт CSV.

Если в диалоге бот уже был запущен до подключения, остановите его через
настройки MAX, затем откройте новую ссылку и нажмите Начать. Веб-админка
содержит полный текст заявки, даже если длинный заказ не помещается в MAX.

## Доставка и данные

- Все заявки сначала записываются в `/data/leads.json`. Сбой MAX не мешает
  форме на сайте и не удаляет заявку.
- События webhook записываются в `/data/max-bot.sqlite` до ответа HTTP 200.
  Повторные события отсеиваются; очередь и привязка переживают перезапуск.
- Для MAX ведётся отдельный учёт доставленных карточек. Telegram chat_id,
  блокировки, пароли и message_id не переносятся.
- После подключения MAX бот пришлёт все имеющиеся новые заявки и заявки для
  перезвона, включая недоставленные раньше. Обработанные архивные заявки
  доступны в админке и экспорте.
- После сетевой ошибки отправка повторяется. Если MAX принял сообщение, но
  ответ потерялся, возможна повторная карточка: у API нет подтверждённого
  ключа идемпотентности для отправки. Статусы заявок при этом не дублируются.
- Отключение выполняется кнопкой в админке или боте. Замена токена отменяет
  все привязки; после этого снова подключите нужные диалоги.
- Сохраняйте весь том data в резервных копиях, включая SQLite. Не используйте
  `docker compose down -v`. Для согласованной копии активной SQLite используйте
  SQLite backup API или остановите app на время резервного копирования.

## Диагностика

```bash
docker compose ps
docker compose logs --since=10m app | grep -E 'max_bot|MAX'
docker compose exec -T app python backend/max_setup.py check
docker compose exec -T app python backend/max_setup.py status
```

- `http_401`: неверный/отозванный токен.
- `username_mismatch`: ник не соответствует токену.
- `network_or_tls_error`: проверьте доступ VPS к platform-api2.max.ru и файл CA.
- `attachment.not.ready`: файл обрабатывается MAX; отправка повторяется.
- «Диалог ещё не подключён»: нужна одноразовая ссылка из `/admin/max`.
- API работает, событий нет: проверьте подписку, DNS сайта, HTTPS/443 и nginx.
- Ручная проверка POST без секретного заголовка должна вернуть 404. Webhook
  проверяет `X-Max-Bot-Api-Secret`, а не браузерный Origin или User-Agent.

MAX требует доверия сертификату Минцифры. Публичный сертификат включён в
`backend/certs/max-ca.pem` и доверяется **только клиентом MAX**, а не всей ОС.
TLS-проверка сертификата и имени хоста включена; `-k` не нужен.
Происхождение и контрольная сумма записаны в `backend/certs/README.md`.

## Локальная разработка

Для локального запуска настройки могут храниться в закрытом
`backend/max-local.json` (права 0600). Этот файл исключён из Git и Docker.
На VPS используются переменные `.env`, локальный файл туда не переносится.
Публичный webhook не может направляться на 127.0.0.1: локально проверяются
код и исходящее API, а входящие события проверяются тестами.

```bash
python3 -m unittest tools.test_max_bot tools.test_admin tools.test_seo_routes
python3 backend/max_setup.py check
```
